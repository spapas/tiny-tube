# Translating Tiny Tube

Tiny Tube uses [go-i18n](https://github.com/nicksnyder/go-i18n) on the server.
The English catalog, `web/locales/en.json`, defines stable message IDs and their
source text. `web/locales/el.json` translates those IDs into Greek. All catalogs
are embedded in the executable; there is no translation service or runtime
frontend dependency.

## Add a language

1. Copy `web/locales/en.json` to a file named with the language's canonical BCP 47
   tag, such as `de.json`, `fr.json`, or `pt-BR.json`.
2. Set `language.name.other` to the language's native name (for example `Deutsch`).
   Translate the message values, keeping the IDs unchanged. An incomplete catalog
   is supported: remove untranslated entries to use their English source messages.
3. Run `go test ./...` and `node --test tests/ui.test.cjs`, then rebuild/restart.
   `dev.bat` already watches catalogs. Release binaries need a new build/deployment.

The file alone registers the language in cookies, the header
selector and browser scripts. No Go, HTML or JavaScript language list needs editing.
The first visit defaults to Greek. A saved browser choice takes precedence; missing translations fall back to English. The selector also works without JavaScript.

A minimal German catalog is:

```json
{
  "language.name": { "other": "Deutsch" },
  "upload.title": { "other": "Video hochladen" },
  "count.videos": {
    "one": "{{.Count}} Video",
    "other": "{{.Count}} Videos"
  }
}
```

## Message format

The files use standard go-i18n JSON objects. Each ID has an `other` value, with
optional `description`, `hash`, `zero`, `one`, `two`, `few`, and `many` fields.
`description` can explain a source message to translators. English owns the IDs;
translations must not introduce new ones.

Use named variables, such as `{{.Name}}`, rather than positional `%s` or `%d`:

```json
"edit.fieldTooLong": {
  "other": "The “{{.Field}}” field is too long. Use fewer characters."
}
```

Keep variable names unchanged. Only named substitutions are supported, so the same
message works in Go templates and browser scripts. Do not add template operations
such as `if`, functions or HTML markup. Output is escaped by `html/template` or
assigned through browser `textContent`. Input titles/descriptions/categories/list
names remain user content and are never translated as message IDs.

For plural messages, supply the forms used by the target language. The server's
CLDR rules and the browser's `Intl.PluralRules` select the form from `Count`.
For example, Russian uses `one`, `few`, `many` and `other`; Arabic additionally
uses `zero` and `two`. A special form can express its count in words, such as
`"zero": "No videos"`. Always keep an `other` form. Missing messages use English
text **and English plural rules**. Numeric `Count` values are localized.

Date month names are `date.month.1` through `date.month.12`; `date.format` controls
their order using `{{.Day}}`, `{{.Month}}`, and `{{.Year}}`. Number formatting uses
the locale automatically. No per-language date/number branches are required.

## Add or change source messages

Add an ID to `en.json`, then refer to that ID in the templates or browser code.
The ID should describe its purpose (`upload.title`), so wording can change without
renaming the ID or breaking translations. Add/update target translations as needed.

Go template:

```gotemplate
{{t "upload.title"}}
{{t "edit.fieldTooLong" "Field" (t "field.title")}}
```

Browser code:

```js
t('edit.fieldTooLong', { Field: t('field.title') })
```

The English JSON file is the source of truth; messages are not extracted from
Greek text or inferred from Go/HTML strings. Startup/tests reject invalid JSON,
unknown IDs, missing language names, unsupported message-template operations and
incompatible named variables. Focused tests verify third-language discovery,
English fallback, plural rules and concurrent requests. JSON API identifiers,
status values and English error text keep their existing representation.
